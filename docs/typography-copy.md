## Terms

- **Overlay text**: all text inside `.desktop-dialog`, `.city-modal` (change mode and the first-run wizard, which reuses the shell), the Add menu and the suggestion list, plus the shared tooltip, the page status chip (`#desktop-status`, with the Reload button it carries after a failed heal) and the `.status` texts (the full-page message inside `#favorites`, the error slots of the city modal and the wizard).
- **Tile text**: text drawn on a tile of the grid (link label and host, letter, weather values, the 2×1 / 1×2 hint caption, weather city line) and the glyph sizes. Together with the cell metrics (`--cell-size`, `--grid-gap`, `--grid-pad`) it is in px.
- **Default font size**: Chrome's "Font size" setting, `webkit.webprefs.default_font_size`, 16 px unless the user changed it. It is the root size that `rem` and the extension-page default `body` size follow.
- **Junk host**: a typed host the URL parser accepts but that cannot name a site: an empty label, a label that begins or ends with `-`, a label with no letter or digit, or a number the parser expands to an IPv4 address (`1` → `0.0.0.1`).
- **Typed host**: the host part of the text typed into the Link field, read by URL grammar before the parser normalizes anything (the exact reading is in decision 7).

## Decisions

1. **Body text is 14 px (item 27).** `body` gets `font-size: var(--font-size-md)` (`newtab.css`). Everything that inherits the body size (inputs, buttons, descriptions, `use your location`, Add menu and suggestion rows, the city field value, the unsized parts of the wizard) goes from 12 to 14 px at the default font size, the "dialog body" size the design system already names. Explicit sizes stay: row, segmented and starter labels 13, hint 12, error and confirm body 14, titles 18. Tile text never inherits from `body` (every tile text rule sets its own px size; verified by the prototype), so the grid does not change. The Settings and Add chrome tiles inherit a 14 px `font` from `body` but draw only icons.
2. **Overlay text is in `rem`; tiles and the cell stay in px (item 36, decision of Kier).** `design-tokens.css`: `--font-size-xs: 0.75rem` (new, 12 px), `--font-size-sm: 0.8125rem` (13), `--font-size-md: 0.875rem` (14), `--font-size-title: 1.125rem` (18): numerically the old px at the default font size, so only decision 1 changes anything at 16 px. The two literal px sizes of `surfaces.css` move to tokens (`.onboarding-wizard__starter-label` → `--font-size-sm`, `.city-field__hint` → `--font-size-xs`). The starter icon letter (12 px inside a fixed 22 px icon box) stays px. Everything in `newtab.css` that sizes tile text stays px, including `--font-size-weather-*`; the cell metrics stay px. **Ruling (марафон, на проверку Киру): the tooltip (`--font-size-sm`), the page status chip and the page-level error text (`--font-size-md`) share the tokens and so also scale with the browser font; the Add menu and suggestion rows scale through the body size; альтернатива: keep the tooltip and the chip in px by splitting the tokens so that only dialogs, the wizard and modals scale; цена ошибки: a token split and the tooltip and chip rows of AS-TYP-01…03, nothing structural.**
3. **A larger font must not clip a control.** `.segmented__option` uses `min-height: calc(var(--control-height) - 2 * var(--control-border-width))` instead of `height` (found by the prototype: "From site" wraps at a 24 px default font in a 420 px dialog; in windows 401–451 px the existing narrow block sets `white-space: nowrap`, which keeps the labels on one line but is not enough at 150%, see the row rule below). Options of a group stay equal in height (flex stretch). No other geometry changes: control min-height 40, dialog width `min(420px, 100vw − 32px)`, label column 100 px, icon-button 36 px, glyph sizes, paddings (so a wrapped label has no extra vertical padding; a `padding-block` that applies only to a wrapped option is backlog 143, not this run). At 150% in windows from 601 px (label beside the control) the Icon group of Add link and Edit link grows from 40 to 58.5 px and so does their dialog (436 → 467.7 for Add link); below 601 px the rows stack (the row rule below) and Edit link is 620.5 px (stage 2 prototype probe); no scenario asserts those numbers, AS-TYP-03 asserts containment. Tall dialogs use the existing scroll with the sticky footer of `docs/layers-low-window.md`.

   **Rows stack earlier at a larger font (S0-01).** The block of `surfaces.css` that puts a dialog row's label above its control changes its query from `@media (max-width: 400px)` to `@media (max-width: 400px), (max-width: 25rem)`. In a media query `rem` is the browser's default font size, so the second term is 400 px at the default size (the two terms are equal and nothing moves), 300 px below it (the first term wins, nothing moves) and 600 px at 150%. Reason: beside the 100 px label column the Icon group has 215–234 px in windows 401–418 px, and at 150% its three one-line labels need 233 px, so the group's `overflow: hidden` cut `Custom` by up to 14.4 px (and `2×2` of the Size group by 1.7 px at 401 px; gate skeptic, `design-review/runs/2026-10-19-fdb66e8-spec-r2/scratch/skeptic-r2-d.out.json`).    **The guard (`test/vocabulary.test.js`).** The repository has no parser and no dependencies, so the test carries a small tokenizer (about 80 lines, in the test file) instead of stripping comments with a regular expression (`//.*$` would cut every line that holds a URL string, e.g. `src/onboardingStarters.js`, `src/weatherApi.js`, `src/icons.js`, `src/widgetsService.js`, and the guard would pass for the wrong reason). States: code; `'…'`; `"…"`; a template literal whose `${…}` is scanned again as code (its literal parts are separate strings); `//` and `/* … */` comments outside strings; regular-expression literals (a `/` after `(`, `,`, `=`, `>` (so also after `=>`), `:`, `[`, `!`, `&`, `|`, `?`, `{`, `}`, `;`, `+`, `-`, `*`, `%`, `<`, `~`, `^` or after `return`, `typeof`, `case`, `in`, `of`, `delete`, `void`, `throw`, `new`, `else`, `do` starts a regex whose body, quotes and `//` included, is skipped; after `)`, `]`, an identifier, a number or a postfix `++` / `--` it is a division). It returns the string parts and the residual code (comments, strings and regex bodies blanked). It must fail loudly, never pass silently: (1) a file that ends inside a string, comment, template or regex throws; (2) the residual code of every `src/*.js` contains no quote character (a tokenizer that went out of sync leaves a stray quote); (3) fixtures run before the scan of `src` and must show that a banned word is found after `"https://…"` on the same line, in a ternary, after `${…}` in a template (`` `up to ${n} favorites` ``), in a string nested in `${…}`, on the second line of a template, after a regex that holds a quote or `\/\/`, after a regex that follows `=>` (`(s) => /"/.test(s)`) or `+`, after a division that follows `)` or `++`, and in a string with an escaped quote, and that the same words in a `//` comment (also after a URL string on the same line) or in a `/* … */` comment are not found. The stage 2 author ran a prototype of this tokenizer (with the operator list above) on `a9b88be`: all 27 files tokenize to a clean end with no residual quote and every fixture behaves as listed; without `>` in the list the `=>` fixture ends in the loud failure (an unterminated string), which is the method working as designed, not a silent pass. Each string part is matched against `favou?rite|widget|desktop|bookmark` (whole words and plurals, any case) and, separately, for ` - `; a hit outside the allowlist fails with `file:line` and the text. The allowlist is keyed by the exact literal text, each entry with a reason class (selector, class name, id, data attribute, storage key, import path, type value); the test prints the hits so that a new entry shows as a diff. `src/newtab.html` is checked by its text nodes and its `aria-label`, `title`, `alt` and `placeholder` attributes. At stage 4 the guard is proven by mutation: the old `Widget not found` text and one hyphen dash put back in a throw-away copy turn it red; the FAIL lines go into the report.

6. **The 1×1 city hint gets the shared tooltip (item 28).** In normal mode, hovering the 1×1 hint tile or focusing it with the keyboard (`:focus-visible`) shows the shared `#tooltip` with the text `Set a city`, with the same placement, Escape and edit-mode rules as the weather tiles whose cell it takes. The face of the tile (pin, dashed border, size) and its accessible name (`aria-label` "Set a city") do not change; no `aria-describedby` (the name is the text) and no native `title` (it would double the custom tooltip). The 2×1, 2×2 (both go through `cell.w === 2` and show the words) and 1×2 hints already show the words and get no tooltip. **Ruling (марафон, на проверку Киру): tooltip, not a permanent caption: the pin stays alone on the face (no room for a caption at the 56 px cell: 51.1 px of text in 54 px of space with the pin still to place; a caption at 64 and 72 would make the three sizes differ); альтернатива: a two-line caption "Set a / city" under a smaller pin at 1×1; цена ошибки: someone who never hovers or tabs to the tile still sees only the pin, as today; changing it later is one rule in `newtab.css` and `createCityHintTile`.**

Pointer, focus, scroll, Escape and edit-mode handling are the existing ones: they act on `[data-tooltip-trigger]` and `showTooltipFor` returns in edit mode.

   **Focus return (R1-03, L0-01).** Closing the city modal puts the focus back on the hint (`applyPendingFocus`, which does not set `suppressTooltipOnFocus`, as for a weather tile), so after a keyboard close (Escape, Cancel, Save unchanged) the hint is `:focus-visible` and its tooltip shows once; the next Escape hides it. No suppression is added: it would also change the weather tiles (Accepted exception 12).
7. **Junk hosts are rejected (item 104).** After the existing checks, `normalizeFavoriteUrl` validates the parsed host with these rules (error `Enter a valid URL`, field `url`, as for every bad address; no new text):
   - an IPv6 literal in brackets: as today;
   - an IPv4 address (the parsed host is four decimal parts): accepted only if the typed host equals it character for character (case-insensitively); so `192.168.0.1` and `http://192.168.0.1:8080/x` pass, while `1`, `127.1`, `2130706433`, `0x7f.0.0.1`, `010.1.1.1`, `1.2.3` (all expanded by the parser) are rejected;
   - any other host: split on `.`; one trailing dot is allowed (a rooted name such as `example.com.`); every other label is 1 or more characters from `[a-z0-9_-]`, does not begin or end with `-`, and contains at least one letter or digit. So `a..b`, `.com`, `..`, `-a.com`, `a-.com`, `a.-b`, `-`, `_` are rejected; `localhost`, `intranet`, `my_host.local`, `_dmarc.example.com`, `a--b.com`, `xn--80ak6aa92e.com` pass.

   **The typed host (R1-09, L0-02).** Read from the typed text by URL grammar, with no normalization: drop an optional `scheme:` (as `hasUrlScheme` decides, any case) and the slashes or backslashes after it; cut at the first `/`, `\`, `?` or `#`; take what follows the last `@` (credentials and several `@` are not part of the host); drop a trailing `:port`. It is compared with the parsed `hostname` without percent-decoding, digit folding or leading-zero removal, so every spelling the parser would normalize is a short form: `192.168.001.1`, a trailing dot (`192.168.0.1.`, although `example.com.` passes: a rooted IP address is not something anyone types), `%31%32%37.0.0.1` and full-width digits are rejected, while `admin@192.168.0.1`, `http://u:p@192.168.0.1:8080/x`, `http://a@b@192.168.0.1/`, `HTTP://192.168.0.1` and `http://192.168.0.1\x` pass. The two tables of AS-TYP-07 were evaluated against this reading in Node 20 by the stage 2 author: 0 mismatches.

   No label-length or total-length rule: the 2000-character link limit stays the only length rule (run 43 tests build 300 and 1990 character hosts). Add, Edit and the wizard starters all go through the same function. The image URL of a custom icon is not host-checked (backlog 102, decided in run 43). **Ruling (марафон, на проверку Киру): number-only short forms of an IPv4 address (`127.1`, `2130706433`, hex and octal parts) and the other spellings the parser normalizes (`192.168.001.1`, a trailing dot after the quad) are rejected because they are far more often a typo than a wish; альтернатива: accept every address the parser can turn into IPv4 and reject only the bare numbers without a dot; цена ошибки: someone who really types `127.1` has to type `127.0.0.1`.**

## Accepted exceptions

1. `manifest.json` `description` ("A quiet new-tab desktop of your favorite links and local weather — nothing else.": both "desktop" and "favorite", shown in `chrome://extensions`), `README.md` and `store/*` use the everyday word or the store's permission wording; they are not the product's UI text, the vocabulary of AS-TYP-04 does not apply to them, and they are published separately (the store text is Kier-only). Revisit with the next store publication.
2. Internal identifiers keep "favorite" and "widget": the `"favorite"` type value, `quietTabWidget:<id>` and `quietTabWidgetsMeta` keys, `#favorites`, `data-widget-id`, class names, function and constant names. They are not visible or announced; renaming storage keys is a format change.
3. Tile text and the cell stay in px (decision of Kier): a larger browser font does not enlarge tile labels, weather values or hint captions; the page zoom does.
4. The starter icon letter (12 px in a 22 px box) stays in px: it is part of an icon.
5. Control geometry stays in px (40 px controls, 100 px label column, 420 px dialog, 36 px icon button): text grows inside it, and where it does not fit the element grows (segmented) or the dialog scrolls (existing mechanism). One line is not guaranteed at font sizes above 150 % or in very narrow windows, and above 150 % a segmented label can still be cut in the 420 px dialog (the Icon group has 266 px beside the label; not measured above 150 %). A wrapped segmented label has no extra vertical padding (backlog 143). A long stored city is cut with an ellipsis in the Edit weather city field earlier at 150% (`Petropavlovsk-Kamchatsky`: 204 px of text in a 189 px field already at 16 px at 1280×800); the field truncates by design and is checked by its own box only.
6. The tooltip, the status chip and the `.status` texts (full-page message, city modal and wizard error slots) scale with the browser font (Ruling in decision 2). At 150 % in a window about 300 px high a long (stale) tooltip is about half the window and `placeTooltip` may put it over its own tile; only its containment in the window is asserted (AS-TYP-03), the placement rule is unchanged.
7. "Layout" stays in four strings (Ruling in decision 4).
8. A stored link that fails the new host rule (seeded; a new one cannot be created) stays on the grid and opens; its Edit → Save reports `Enter a valid URL` until the address is fixed, because Edit always sends the url.
9. IPv4 short forms and the other spellings the parser normalizes are rejected (Ruling in decision 7). A custom icon URL gets no host check (backlog 102).
10. The 1×1 hint gets its words only on hover or focus (Ruling in decision 6); touch has no hover, which is the case today.
11. Wording of the unreadable-data message is only re-worded; the UI does not show it until its reset flow, row Р51 (an unreadable meta draws an empty grid with no text today).
12. Programmatic focus return to the 1×1 hint (after the city modal closes with the keyboard, after the "city was removed elsewhere" retry recovery) shows its tooltip when the hint is `:focus-visible`, as a weather tile's tooltip does after a keyboard Save (`docs/city-modal-focus-copy.md` decision 1). It is not suppressed: `applyPendingFocus` is shared with the weather tiles and the tooltip is not announced (no `aria-describedby`).
13. A browser font size below the default scales the overlay text down too (measured at 12 px "Small": inputs and buttons 9 → 10.5 px, row labels 13 → 9.75, titles 18 → 13.5; at 9 px 7.9 / 7.3 / 10.1, gate probe). It follows the decision of Kier (rem) in both directions; there is no lower bound of our own, and the ring-to-text gap of the `use your location` link (3 px ring, about 2.9 px of space) is not re-measured at 12 px.

## Non-goals

- A label-length or total-length rule for hosts, a TLD requirement, DNS or reachability checks, the host check of a custom icon URL.
- Renaming code identifiers or storage keys; the manifest `description`, README and store texts (Accepted exception 1).
- The reset flow for unreadable data and the text "Your grid couldn't be read." (Р51), tab-visibility refresh (Р50), any change to colours, focus rings, or weather behaviour.
